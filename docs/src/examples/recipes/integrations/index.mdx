# Integrations

BlueForm renders no UI of its own. **All form logic is written once** (rules, conditions, computed values, labels) and each UI library only displays it. Field `props` are typed by the component you map, so a config written for Mantine takes Mantine's props, with autocomplete and type errors. Swapping libraries means rewriting the adapters and the `props`, never the logic.

## Live demos

Each demo renders **the same logic** with a different library: [Mantine](./mantine.mdx) · [shadcn/ui](./shadcn.mdx) · [Ant Design](./antd.mdx) · [Material UI](./mui.mdx) · [animal-island-ui](./animal-island.mdx). They are built from [`docs/integrations`](https://github.com/bonniss/react-headless-form/tree/main/docs/integrations) with these docs and served from this site.

In every demo: switch the language in the header, submit with the header button (it targets the form by `form="demo-form"`), click the error count to jump to a field, and read the submitted payload in the drawer, where computed values are tagged.

## One logic, UI-only differences

The numbers below are counted from the demo sources when the docs are built. Every rule, condition and computed value sits in `shared/logic.ts`; **each library's files have none**. A library's `config.tsx` only spreads that logic and adds `type` and its own `props`:

`shared/types.ts` is the contract for the demo layout only (`Root`, `SubmitButton`, `LanguageSwitch`, `Section`, `LinesList`). Field props are **not** a shared type: each library's adapters take that library's own props. The demo stage around them (header, error list, payload drawer) is shared too.

## Props typed by the UI library

An adapter takes the library's component props, minus what `useField()` controls:

```tsx
// mantine/fields.tsx
export type TextFieldProps = Omit<TextInputProps, 'value' | 'onChange' | 'onBlur' | 'error' | 'label' | ...>
function TextField(props: TextFieldProps) {
  const { value, onChange, ...field } = useField()
  return <TextInput {...props} value={value ?? ''} onChange={e => onChange(e.currentTarget.value)} ... />
}
```

`props` in the config is then `ComponentProps` of the mapped component, so each library's config uses its own API, with autocomplete and type errors:

<Tabs>

  </Tab>
  <Tab label="Material UI">
    ```tsx
    weight: { type: 'text', ...logic.weight, props: { slotProps: { input: { endAdornment: <InputAdornment position="end">kg</InputAdornment> } } } },

    ```

A prop the component does not have, or a wrong value, is a type error. [`type-checks.tsx`](https://github.com/bonniss/react-headless-form/blob/main/docs/integrations/type-checks.tsx) asserts this for each library (`// @ts-expect-error`), and the docs build type-checks it.

## Event signatures

`onChange` from `useField()` accepts a value or a native event; passing the value explicitly is clearer:

| Library | Text input | Select | Boolean |
|---|---|---|---|
| Mantine | event → `e.currentTarget.value` | value | event → `e.currentTarget.checked` |
| shadcn/ui (native) | event → `e.target.value` | event (native `<select>`); `onValueChange` with Radix | event; `onCheckedChange` with Radix |
| Ant Design | event → `e.target.value` | value | event → `e.target.checked` |
| Material UI | event → `e.target.value` | event (`TextField select`) | event → `e.target.checked` |
| animal-island-ui | event → `e.target.value` | key (options use `key`) | `Switch` → checked |

## Bring your own library

1. Call `useField()` in a field component and destructure what you need.
2. Map `value` to the library's value prop and call `onChange(value)` from its change handler.
3. Wire `label`, `errorMessage`, `required`, `disabled`, `readOnly` and `id` (for label association).

Recipes without a built demo: [Chakra UI](./chakra-ui.mdx), [PrimeReact](./prime-react.mdx), [Arco Design](./arco-design.mdx), [Semi Design](./semi-design.mdx), [TDesign](./tdesign.mdx), [React Native Web](./react-native-web.mdx).

## Validation libraries

Any [Standard Schema](https://standardschema.dev) works directly with the `schema` prop: [Zod](./zod.mdx), [Valibot](./valibot.mdx), [ArkType](./arktype.mdx). Other libraries use `formOptions.resolver`: [Yup](./yup.mdx), [Ajv](./ajv.mdx). See [Schema validation](../../../guide/core/schema-validation.mdx).

## Running the demos locally

In `docs/`, `pnpm dev` starts the docs and the demos together (the demos on Vite, port 5180); `pnpm dev:docs` or `pnpm dev:demos` start one of them. `pnpm build` builds both.
