# Integrations

BlueForm renders no UI of its own: the config holds the logic (rules, conditions, computed values, labels) and a UI library displays it. Field `props` are typed by the component you map, so a config written for Mantine takes Mantine's props, with autocomplete and type errors.

## Live demos

The same registration form, written for each library: [Mantine](./mantine.mdx) · [shadcn/ui](./shadcn.mdx) · [Ant Design](./antd.mdx) · [Material UI](./mui.mdx) · [animal-island-ui](./animal-island.mdx). Each demo is self-contained: copy its `fields.tsx` (adapters) and `form.tsx` (setup and config) into your app. Sources: [`docs/integrations`](https://github.com/bonniss/react-headless-form/tree/main/docs/integrations).

In every demo: switch the language in the header, submit with the header button (`form="demo-form"`), click the error count to jump to a field, and read the submitted payload in the drawer.

| Field | Demonstrates |
|---|---|
| form title | `renderRoot`: the form's own layout (title, responsive grid, submit button) |
| `name`, `email` | `required`, `pattern`, translated messages; `placeholder` translated with `translateProps` |
| `ticket` | a select; each adapter maps the options to its library's prop |
| `studentId` | JSON condition `visible` (student tickets only); left out of the payload when hidden |
| `promoCode` | JSON condition `disabled` (not for student tickets) |
| `guests` | array with `maxLength: 3`; each guest's name is required, with the error on its own row |
| `invoice` → `billing` | a checkbox showing a nested section with its own rules |
| `total` | computed value: ticket price + $100 per guest |

## Props typed by the UI library

An adapter takes the library's component props, minus what `useField()` controls, with [`AdapterProps`](../../../guide/core/field-authoring/use-field.mdx#typing-an-adapters-props):

```tsx
// mantine/fields.tsx: Mantine's TextInput props minus value / onChange / label / disabled / … and `error`
export type TextFieldProps = AdapterProps<TextInputProps, 'error' | 'withAsterisk'>
function TextField(props: TextFieldProps) {
  const { value, onChange, ...field } = useField()
  return <TextInput {...props} value={value ?? ''} onChange={e => onChange(e.currentTarget.value)} ... />
}
```

`props` in the config is then `ComponentProps` of the mapped component, so each config uses its library's API:

import { Tab, Tabs } from '@rspress/core/theme';

<Tabs>

    ```tsx
    promoCode: { type: 'text', label: 'field.promoCode', props: { helperText: 'hint.promoCode' } },

    ```

A prop the component does not have, or a wrong value, is a type error. [`type-checks.tsx`](https://github.com/bonniss/react-headless-form/blob/main/docs/integrations/type-checks.tsx) asserts this for each library (`// @ts-expect-error`), and the docs build type-checks it.

Text props such as `placeholder` are translated when listed in `i18nConfig.translateProps` (the demos list `placeholder`, `description` and `helperText`). Nothing is defaulted: an adapter decides what to show when a prop is missing.

## Event signatures

`onChange` from `useField()` accepts a value or a native event; passing the value explicitly is clearer:

| Library | Text input | Select | Boolean |
|---|---|---|---|
| Mantine | event → `e.currentTarget.value` | value | event → `e.currentTarget.checked` |
| shadcn/ui (native) | event → `e.target.value` | event (native `<select>`); `onValueChange` with Radix | event; `onCheckedChange` with Radix |
| Ant Design | event → `e.target.value` | value | event → `e.target.checked` |
| Material UI | event → `e.target.value` | event (`TextField select`) | event → `e.target.checked` |
| animal-island-ui | event → `e.target.value` | key (options use `key`) | `Switch` → checked |

## Bring your own library

1. Call `useField()` in a field component and destructure what you need.
2. Map `value` to the library's value prop and call `onChange(value)` from its change handler.
3. Wire `label`, `errorMessage`, `required`, `disabled`, `readOnly` and `id` (for label association).

Recipes without a built demo: [Chakra UI](./chakra-ui.mdx), [PrimeReact](./prime-react.mdx), [Arco Design](./arco-design.mdx), [Semi Design](./semi-design.mdx), [TDesign](./tdesign.mdx), [React Native Web](./react-native-web.mdx).

## Validation libraries

Any [Standard Schema](https://standardschema.dev) works directly with the `schema` prop: [Zod](./zod.mdx), [Valibot](./valibot.mdx), [ArkType](./arktype.mdx). Other libraries use `formOptions.resolver`: [Yup](./yup.mdx), [Ajv](./ajv.mdx). See [Schema validation](../../../guide/core/schema-validation.mdx).

## Running the demos locally

In `docs/`, `pnpm dev` starts the docs and the demos together (the demos on Vite, port 5180); `pnpm dev:docs` or `pnpm dev:demos` start one of them. `pnpm build` builds both.
