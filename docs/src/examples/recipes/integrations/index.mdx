# Integrations

BlueForm renders no UI of its own. **All form logic lives in one config**: rules, conditions, computed values, arrays, i18n. A UI library only provides the components that display it. Swapping libraries means rewriting a small adapter file, never the logic.

## Live demos

Each demo renders **the same config** with a different library: [Mantine](./mantine.mdx) · [shadcn/ui](./shadcn.mdx) · [Ant Design](./antd.mdx) · [Material UI](./mui.mdx) · [animal-island-ui](./animal-island.mdx). They are built from [`docs/integrations`](https://github.com/bonniss/react-headless-form/tree/main/docs/integrations) with these docs and served from this site.

In every demo: switch the language in the header, submit with the header button (it targets the form by `form="demo-form"`), click the error count to jump to a field, and read the submitted payload in the drawer, where computed values are tagged.

## What each field shows

| Field | Demonstrates |
|---|---|
| `name` | `required` with a translated message |
| `slug` | editable computed value: follows the name until you edit it |
| `email` | `pattern` rule |
| `role` → `adminCode` | JSON condition `visible`; a hidden field is left out of the payload |
| `role` → `bio` | JSON condition `disabled` |
| `health.weight` / `height` → `bmi` → `bmiClass` | nested section, computes reading their section through `ctx.scope`, a computed chain |
| `settings.*` | nested section with a checkbox and a select |
| `lines` | array with `maxLength: 3`; required row fields, with each error on its own row (`lines.1.price`) |
| `lines.*.total` → `subtotal` → `vat` → `grandTotal` | per-row computed values and an aggregate chain |
| language switch | labels, option labels, validation messages (also those already shown) |

## One logic, UI-only differences

The numbers below are counted from the demo sources when the docs are built. Every rule, condition and computed value sits in the shared config, and **every adapter file has none**: what differs between libraries is only which component displays a value.

`shared/types.ts` is the contract every library implements: four field types (`text`, `longText`, `select`, `checkbox`) and the layout pieces (`Root`, `SubmitButton`, `LanguageSwitch`, `Section`, `LinesList`). The demo stage around them (header, error list, payload drawer) is shared too.

## Event signatures

`onChange` from `useField()` accepts a value or a native event; passing the value explicitly is clearer:

| Library | Text input | Select | Boolean |
|---|---|---|---|
| Mantine | event → `e.currentTarget.value` | value | event → `e.currentTarget.checked` |
| shadcn/ui (native) | event → `e.target.value` | event (native `<select>`); `onValueChange` with Radix | event; `onCheckedChange` with Radix |
| Ant Design | event → `e.target.value` | value | event → `e.target.checked` |
| Material UI | event → `e.target.value` | event (`TextField select`) | event → `e.target.checked` |
| animal-island-ui | event → `e.target.value` | key (options use `key`) | `Switch` → checked |

## Bring your own library

1. Call `useField()` in a field component and destructure what you need.
2. Map `value` to the library's value prop and call `onChange(value)` from its change handler.
3. Wire `label`, `errorMessage`, `required`, `disabled`, `readOnly` and `id` (for label association).

Recipes without a built demo: [Chakra UI](./chakra-ui.mdx), [PrimeReact](./prime-react.mdx), [Arco Design](./arco-design.mdx), [Semi Design](./semi-design.mdx), [TDesign](./tdesign.mdx), [React Native Web](./react-native-web.mdx).

## Validation libraries

Any [Standard Schema](https://standardschema.dev) works directly with the `schema` prop: [Zod](./zod.mdx), [Valibot](./valibot.mdx), [ArkType](./arktype.mdx). Other libraries use `formOptions.resolver`: [Yup](./yup.mdx), [Ajv](./ajv.mdx). See [Schema validation](../../../guide/core/schema-validation.mdx).

## Running the demos locally

In `docs/`, `pnpm dev` starts the docs and the demos together (the demos on Vite, port 5180); `pnpm dev:docs` or `pnpm dev:demos` start one of them. `pnpm build` builds both.
