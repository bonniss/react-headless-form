# Integrations

BlueForm renders no UI. You connect your UI kit with small **adapters**: an adapter is a React component that calls `useField()` and renders one of your kit's inputs (the Guide calls it a [field component](../../../guide/core/field-authoring/index.mdx)). The config keeps the logic — rules, conditions, computed values — and its `props` are typed by your kit's own components.

New to BlueForm? Read the [Quick start](../../../guide/start/quick-start.mdx) first; this page builds on it.

## Connect your UI kit {#bring-your-own-library}

### Write an adapter per input type

One adapter per kind of input your forms use (text, select, checkbox…). It reads the field from `useField()` and hands it to your component:

```tsx
import { Input, type InputProps } from "my-ui"
import { type AdapterProps, useField } from "react-headless-form"

// your component's props, minus what useField() provides, minus `error` (set below)
export type TextFieldProps = AdapterProps<InputProps, "error">

export function TextField(props: TextFieldProps) {
  const { value, onChange, onBlur, ref, label, description, errorMessage, required, disabled, readOnly } =
    useField()
  return (
    <Input
      {...props}
      ref={ref}
      label={label}
      hint={description}
      error={errorMessage}
      required={required}
      disabled={disabled}
      readOnly={readOnly}
      value={value ?? ""}
      onChange={(e) => onChange(e.target.value)}
      onBlur={onBlur}
    />
  )
}
```

- **Pass the value to `onChange`.** Check what your component's change handler gives you — a value, a DOM event or an object — and extract the value (`e.target.value`, `checked`, `e.value`…).
- **Attach `ref`** so the form can focus a field with an error.
- [`AdapterProps`](../../../guide/core/field-authoring/use-field.mdx#typing-an-adapters-props) removes what `useField()` provides (`value`, `onChange`, `label`, `disabled`, …) from your component's props; its second argument lists the props the adapter sets itself (here `error`), so a config cannot override them.

### Register them

```tsx
import { defineMapping, setupForm } from "react-headless-form"

export const [Form, defineConfig] = setupForm({
  renderRoot: ({ children, onSubmit }) => <form onSubmit={onSubmit}>{children}</form>,
  fieldMapping: defineMapping({ text: TextField, select: SelectField, checkbox: CheckboxField }),
})
```

The keys (`text`, `select`, `checkbox`) are the `type` values of your config. `renderRoot` draws the form itself (its layout, a submit button). `array`, `section`, `inline` and `hidden` are built-in types and need no adapter.

### Write configs with your kit's props

A field's `props` are typed by its adapter, so each config speaks its kit's API:

import { Tab, Tabs } from '@rspress/core/theme';

<Tabs>
  <Tab label="Mantine">
    ```tsx
    email: { type: "text", label: "Email", props: { type: "email", leftSection: "@" } },
    ticket: { type: "select", label: "Ticket", props: { data: [{ value: "student", label: "Student" }] } },
    ```
  </Tab>
  <Tab label="Ant Design">
    ```tsx
    email: { type: "text", label: "Email", props: { type: "email", prefix: "@" } },
    ticket: { type: "select", label: "Ticket", props: { options: [{ value: "student", label: "Student" }] } },
    ```
  </Tab>
  <Tab label="Material UI">
    ```tsx
    promoCode: { type: "text", label: "Promo code", props: { helperText: "Not for student tickets" } },
    ticket: { type: "select", label: "Ticket", props: { children: [<MenuItem key="student" value="student">Student</MenuItem>] } },
    ```
  </Tab>
</Tabs>

A prop the component does not have, or a wrong value, is a type error (see [`type-checks.tsx`](https://github.com/bonniss/react-headless-form/blob/main/docs/integrations/type-checks.tsx)).

### Render the form

Render `Form` inside your kit's provider, as you would any component:

```tsx
<Form<Registration>
  config={config}
  defaultValues={{ ticket: "standard", guests: [] }}
  onSubmit={(data) => save(data)}
/>
```

Labels are plain strings unless you add [i18n](../../../guide/core/i18n.mdx): with `i18nConfig.t`, labels, descriptions, placeholders and error messages are translated. Use the field's `description` for help text (translated, read with `useField().description`) and pass it to the library's prop, e.g. Mantine `description` or MUI `helperText`.

:::info What to copy from a demo
- **`fields.tsx`**: the adapters, as is.
- **`form.tsx`**: `setupForm` and the config. It imports `useT` and `FORM_ID` from the docs' demo stage: use your own i18n hook and drop the form `id`.
- **Not needed in your app**: `main.tsx` and `docs/integrations/shared/*` (language switch, header submit button, error list, payload drawer).

The demos render `Form` with `i18nConfig` (`t`, `validationTranslation`) and `formOptions={{ shouldUnregister: true }}`, which drops hidden fields from the payload. With arrays, read [pitfall 14](../../../guide/start/pitfalls.mdx) before keeping `shouldUnregister`.
:::

## Validation libraries

Zod, Valibot, ArkType and Yup (1.7+) implement Standard Schema: pass them to the `schema` prop. For Ajv (JSON Schema) or any other react-hook-form resolver, use `formOptions.resolver`. With a schema, field `rules` are not used; set `required: true` on a field to show its `*`. See the [Schema example](../../foundational/schema-form.mdx).
